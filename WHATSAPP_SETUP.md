# Подключение WhatsApp к CRM

Пошаговая настройка официального WhatsApp Business Cloud API (Meta). Код уже
готов и ждёт только ключей: пока переменные окружения не заданы, раздел
«WhatsApp» в админке открывается, но сообщения не приходят и не отправляются.

**Важно до начала.** Вход в Meta, проверка бизнеса, подключение номера и выдача
токенов — только ваши действия в вашем кабинете.

---

## Шаг 0. Решите, какой номер подключаете

Два варианта, выберите один:

1. **Отдельный номер только для CRM** — проще всего. Номер не должен быть
   зарегистрирован ни в обычном WhatsApp, ни в WhatsApp Business App. Если он
   где-то зарегистрирован — сначала удалите там аккаунт, иначе Meta его не
   примет.
2. **Действующий +992070217755, который уже используется в приложении** — тогда
   нужен режим **Coexistence**: номер остаётся в приложении на телефоне и
   одновременно работает через API. Ограничения этого режима: нет синей
   галочки, нет звонков через этот путь, не синхронизируются групповые чаты,
   приложение нельзя удалять с телефона (его нужно открывать примерно раз в 13
   дней), пропускная способность ниже. Доступность Coexistence зависит от
   страны и аккаунта — это видно только в самом процессе подключения.

Пока вы не решили — делайте всё на **бесплатном тестовом номере Meta** (шаг 2).
На нём проверяется вся цепочка, не трогая рабочий номер.

---

## Шаг 1. Приложение в Meta for Developers

1. Откройте <https://developers.facebook.com/apps> под аккаунтом, у которого
   есть доступ к вашему Meta Business.
2. Создайте приложение типа **Business**. Либо используйте существующее — то
   самое, где уже настроена Facebook-интеграция (`FB_APP_ID` в проекте).
3. В приложении: **Add product → WhatsApp → Set up**.
4. Привяжите приложение к вашему **Meta Business Account**.

---

## Шаг 2. Идентификаторы номера

В приложении откройте **WhatsApp → API Setup**. Там сразу выдаётся тестовый
номер и видны значения:

| Что на экране | Куда положить |
|---|---|
| **Phone number ID** | `WHATSAPP_PHONE_NUMBER_ID` |
| **WhatsApp Business Account ID** | `WHATSAPP_BUSINESS_ACCOUNT_ID` |
| **Temporary access token** | временный, живёт 24 часа — для проверки годится, для работы нет (шаг 3) |

На этой же странице в разделе **To** добавьте до 5 своих номеров-получателей:
на тестовом номере писать можно только им.

---

## Шаг 3. Постоянный токен доступа

Временный токен протухнет через сутки. Для работы нужен токен System User:

1. <https://business.facebook.com/settings> → **Users → System users**.
2. **Add** → имя (например `mimi-crm`) → роль **Admin**.
3. **Add assets** → ваше приложение и ваш WhatsApp Business Account → полный
   доступ.
4. **Generate new token** → выберите приложение → права
   **`whatsapp_business_messaging`** и **`whatsapp_business_management`** →
   срок **Never**.
5. Скопируйте токен **сразу** — второй раз он не показывается.

Токен кладётся в `WHATSAPP_ACCESS_TOKEN`. Никому его не пересылайте — он даёт
право писать от имени вашего номера.

---

## Шаг 4. App Secret

**Settings → Basic → App Secret → Show**. Значение кладётся в
`WHATSAPP_APP_SECRET`.

Им проверяется подпись каждого запроса от Meta. Без него в production webhook
отклоняет все события — это намеренно: иначе на наш адрес мог бы писать кто
угодно.

---

## Шаг 5. Переменные окружения

В Vercel: **Project → Settings → Environment Variables**. Добавьте для
окружения Production (и Preview, если нужно):

```
WHATSAPP_ACCESS_TOKEN        — постоянный токен из шага 3
WHATSAPP_PHONE_NUMBER_ID     — из шага 2
WHATSAPP_BUSINESS_ACCOUNT_ID — из шага 2
WHATSAPP_APP_SECRET          — из шага 4
WHATSAPP_VERIFY_TOKEN        — придумайте любую длинную строку сами
WHATSAPP_ALLOWED_RECIPIENTS  — на время тестов: ваши номера через запятую
WHATSAPP_LINK_NUMBER         — необязательно; номер для ссылок под Reels
```

`WHATSAPP_ALLOWED_RECIPIENTS` — страховка: пока в нём перечислены номера,
отправка возможна только им, и случайное сообщение живому клиенту невозможно.
Когда всё проверите — очистите это поле.

После добавления переменных нужен **новый деплой**: Vercel подхватывает
переменные только при сборке.

---

## Шаг 6. Webhook

1. В приложении: **WhatsApp → Configuration → Webhook → Edit**.
2. **Callback URL**: `https://mimitj.agency/api/whatsapp/webhook`
3. **Verify token**: ровно та строка, что в `WHATSAPP_VERIFY_TOKEN`.
4. **Verify and save** — Meta сразу дёрнет адрес и должна показать успех. Если
   ошибка: проверьте, что деплой с переменными уже прошёл.
5. **Manage → подпишитесь на поле `messages`** (обязательно: без этого webhook
   проверку пройдёт, но события приходить не будут — самая частая причина
   «всё настроил, но тишина»).

---

## Шаг 7. Подключение реального номера

Делается, когда всё проверено на тестовом.

1. **WhatsApp → API Setup → Add phone number**.
2. Укажите отображаемое имя (его проверяет модерация Meta) и категорию бизнеса.
3. Подтвердите номер кодом из SMS или звонка.
4. Для варианта Coexistence подключение идёт через сканирование QR-кода в
   приложении WhatsApp Business на телефоне, по подсказкам Meta на экране.
5. После подключения **замените `WHATSAPP_PHONE_NUMBER_ID`** на id нового
   номера и сделайте новый деплой.

Про лимиты: новый номер начинает с ограничения по числу новых диалогов в сутки,
оно растёт по мере нормальной переписки. Для снятия ограничений нужна
верификация бизнеса в Meta.

---

## Шаг 8. Проверка

**Приём сообщений.**
1. Напишите с личного телефона на подключённый номер.
2. Откройте в админке **WhatsApp**. В течение 15 секунд (интервал опроса)
   диалог появится в списке со счётчиком непрочитанных.
3. Если ничего нет — проверьте подписку на поле `messages` (шаг 6.5) и логи
   деплоя в Vercel (ищите строки `[whatsapp]`).

**Отправка.**
1. Откройте диалог, напишите ответ, нажмите «Отправить».
2. Сообщение появится справа с галочкой; когда клиент получит и прочитает,
   галочки станут двойными и позеленеют.
3. Ошибка «Прошло больше 24 часов» — это правило Meta, не сбой: писать первым
   вне 24-часового окна можно только заранее одобренным шаблоном.

**Источник обращения.**
1. В разделе WhatsApp → вкладка **Ссылки** создайте ссылку под публикацию.
2. Откройте короткую ссылку с телефона — WhatsApp откроется с готовым текстом,
   в котором есть метка вида `#m-reels07`.
3. Отправьте это сообщение. В CRM метка будет вырезана из текста, а в карточке
   клиента появятся источник, кампания и название публикации.
4. Переход из рекламы Click-to-WhatsApp определяется автоматически: Meta сама
   присылает данные объявления.

---

## Что важно понимать про источники

- **Платная реклама Instagram/Facebook** с кнопкой WhatsApp — источник
  определяется автоматически, вместе с текстом объявления и идентификатором
  клика. Площадку (Instagram или Facebook) Meta в этих данных не передаёт.
- **Органические Reels и Stories** — Meta не передаёт о них ничего. Поэтому
  работают ссылки с метками: по одной на публикацию. В подписи к Reels
  Instagram ссылку кликабельной не делает — размещайте её в био или в стикере
  Stories.
- **Клиент может стереть подставленный текст** перед отправкой. Тогда метки не
  будет, и источник останется неизвестным. Мы его не угадываем — в карточке
  честно пишется «Неизвестный источник».
- **Повторные обращения** не затирают первоначальный источник: новый
  подтверждённый переход добавляется отдельной записью в историю
  взаимодействий.

## Стоимость

Meta берёт плату за диалоги; тарифы зависят от страны и типа диалога и
меняются. С 1 октября 2026 года платными стали и ответы внутри 24-часового
окна. Актуальные цены смотрите в кабинете Meta перед запуском — ориентироваться
на старые статьи не стоит.
