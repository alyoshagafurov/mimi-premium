# Переезд в Франкфурт: что нажать

Порядок важен. Пункты 1–3 не влияют на работающий сайт, переключение
происходит только в пункте 4, и откат — одна переменная.

## 1. Создать базу в новом регионе (Neon)
1. console.neon.tech → **New Project**
2. Region: **Europe (Frankfurt) — eu-central-1**
3. Postgres version — та же, что сейчас
4. Скопировать **обе** строки подключения:
   - **Pooled connection** (хост с `-pooler`) — она пойдёт в `DATABASE_URL`
   - Direct — понадобится для заливки дампа

## 2. Перелить данные — через сам Neon (не через ноутбук!)

База 131 МБ, из них **99 МБ — таблица MediaAsset** (картинки лежат в базе
как base64). Тянуть это через канал Душанбе → Вирджиния → Франкфурт
бессмысленно: замерено 0.7 МБ/мин, дамп вставал совсем.

Правильный путь — **Neon переливает сам, внутри AWS**:

1. Открыть **новый** проект (Франкфурт) → кнопка **Import data** (справа сверху)
2. Выбрать импорт из другой базы Postgres
3. Вставить **DIRECT** строку подключения **старого** проекта (us-east-1)
4. Запустить и дождаться (обычно минуты — трафик идёт внутри AWS)

⚠️ Пока идёт импорт, не добавляйте данные на сайте — то, что появится после
снятия снимка, в новую базу не попадёт.

### Запасной вариант (если Import data не сработал)
Скрипт `scripts/migrate-neon-region.sh` делает то же через локальную машину.
Требует клиент Postgres не старше сервера (`brew install postgresql@17`).
На медленном канале может занять часы — запускать на ночь.

## 3. Задать регион функций Vercel
В `vercel.json` добавить в корень объекта:
```json
"regions": ["fra1"]
```
⚠️ Не деплоить это раньше пункта 4 — иначе функции переедут во Франкфурт,
а база останется в Вирджинии, и каждый запрос поедет через Атлантику.

## 4. Переключить (момент истины)
Vercel → Project → Settings → Environment Variables → `DATABASE_URL`
→ вставить **Pooled** строку нового проекта → Save → **Redeploy**.

Сразу после деплоя:
- открыть сайт, зайти в админку, проверить «Клиенты» и «Продажи»
- `curl -s https://www.mimitj.agency/api/health` — покажет время запроса к базе

## 5. Не давать базе засыпать
Free tier Neon спит после ~5 минут простоя (первый запрос потом стоит ~2.5 с).
Vercel Hobby разрешает крон только раз в сутки, поэтому проще внешним пингером:
- cron-job.org (бесплатно) → URL `https://www.mimitj.agency/api/health`, каждые 5 минут

Либо платный тариф Neon — там компьют не засыпает вообще.

## Откат
Вернуть прежний `DATABASE_URL` в Vercel, убрать `"regions"` из `vercel.json`,
Redeploy. Старая база всё это время живая и с данными.

## Когда удалять старую базу
Через несколько дней работы на новой, убедившись, что всё в порядке.
